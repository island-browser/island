## Goals

1. Sign-ins and site storage survive ⌘Q, a reboot, and an emptied `/tmp`, in each space separately
   (ROADMAP F-1).
2. A local process can no longer drive the person's signed-in tabs through an always-open CDP port
   (ROADMAP A-2).
3. A crash or `kill -9` loses at most the last few seconds of tab and space changes (ROADMAP F-2).
4. An Arc user can move to Island before 2026-12-22. Spaces, pinned tabs, folders and Favorites
   come over, and importing again creates no duplicates (ROADMAP F-6).
5. Links go to the space they belong to: a host can be routed to a space (ROADMAP §4.2 item 6).
6. Every Island-owned file can be backed up to one file and restored on a clean HOME (ROADMAP F-7).
7. The user guide has a "Moving from Arc" page that describes only what was built.

## Non-goals

- Anything in the 0.9 scope: bookmarks and favorites UI, the favorite virtual tabs, AR-1…AR-5, and
  the T4/T4b/T8b/T9/OF-F/FU-b follow-ups.
- The B1–B14 "ordinary browser" handlers (permissions, JS dialogs, TLS errors, downloads UI,
  fullscreen) and becoming the default browser. These are 0.11 (ROADMAP §4.3). Routing external
  `open` URLs therefore arrives with 0.11; the routing seam here is built for it (§2.5).
- The real Keychain, code signing and notarization (0.13, Q3 option a).
- Sync, profiles, cloud backup, scheduled or automatic backups, and multiple windows.
- Importing Arc's unpinned ("Today") tabs, Arc Boosts, Easels, Notes or Little Arc, and importing
  history or passwords from any browser.
- Dia or Zen import code. Only a spike report is in scope (§2.4.4).
- A general "Clear browsing data" page. §2.1 R-D7 covers only the per-space reset that persistent
  data makes necessary.
- Migrating existing web data. Nothing is on disk today (§2.1), so there is nothing to carry over.

## 1. User stories

- As a person, I sign in to a site in my Work space, quit, and I am still signed in when I come
  back. My Personal space stays signed out of that site.
- As a person, I do not want another program on my Mac to read or drive my signed-in tabs.
- As a person, after a crash I get back the tabs I had a few seconds earlier.
- As an Arc user, I import once and get my spaces with their colors, pinned tabs, pinned folders as
  bookmark folders, and my Favorites. Importing again later does not double anything.
- As a person, I tell Island that `github.com` always opens in Work, and new GitHub tabs go there.
- As a person, I back up Island to one file and restore it on a new Mac or a clean account.

### 2.1 Persistent per-space web data

**Current behaviour (verified).**

- `CefSettings.root_cache_path` is `/tmp/island_cef_cache` (`src/main/app_runtime.cc:23`), or
  `ISLAND_DEV_CACHE_DIR` when that is set (`:27-30`).
- `persist_session_cookies` is `false` (`:34`).
- Each `Space` creates its own `CefRequestContext` lazily. `request_context()` always calls
  `CreateRequestContextIfNeeded("")` (`src/main/space.cc:318-319`), so `cache_path` is never set
  (`:296-297`).
- By the CEF contract, an empty context `cache_path` is "incognito mode": "no profile-specific data
  is persisted to disk … localStorage will only persist … if a cache path is specified" (pinned CEF
  `include/internal/cef_types.h`, `CefRequestContextSettings.cache_path`).
- Every space browser, the Peek card included, uses its space's context
  (`browser_window.cc:766`, `:3943`, `:4144`, `:5070`). Local Island pages use the global context
  (`local_page.cc:149`, `nullptr`).
- The code therefore persists no cookies or site storage at all. B1/B2 confirm this at runtime in
  rollout step 0.

**ROADMAP correction.** ROADMAP Q3(b) and F-1 only ask for a `cache_path`. That is not enough.
With `persist_session_cookies=false`, cookies without an expiry are still dropped at quit, even on
a disk-backed context, and many sites sign in with exactly such cookies. CEF lets each context
override the global value; the override is ignored only while `cache_path` is empty (`cef_types.h`,
`CefRequestContextSettings.persist_session_cookies`). R-D2 therefore sets it per space.

**Requirements.**

- **R-D1 — One data-directory helper.**
  - Add CEF-free `src/main/data_paths.{h,cc}` with `IslandDataDirectory()` (the directory the
    stores use today) and `IslandWebDataRoot()`.
  - Today five copies of the platform rule exist: `session_store.cc:328-353`,
    `prefs_store.cc:395-420`, `bookmark_store.cc:852-877`, `report_store.cc:189-214` and
    `src/agent/agent_endpoint.cc:59-82`. The four `src/main` stores delegate to the new helper with
    unchanged results. `src/agent` stays CEF-free and standalone, so it keeps its own copy, and a
    test pins the two copies equal.
  - `IslandWebDataRoot()`:
    - macOS: `~/Library/Application Support/Island/Web Data`.
    - Linux: `$XDG_DATA_HOME/Island/Web Data`, or `~/.local/share/Island/Web Data`.
    - Windows: `%LOCALAPPDATA%\Island\Web Data`, because caches must not roam with `%APPDATA%`.
    - When `ISLAND_DEV_CACHE_DIR` is set, the root is that directory. Developer and helper runs
      therefore never touch the person's profile.
  - **Check:** `DataPathsTest.StoresKeepTheirCurrentPaths`;
    `DataPathsTest.WebDataRootFollowsDevCacheDir`; `DataPathsTest.AgentEndpointPathMatches`.
- **R-D2 — The root and each space are disk-backed.**
  - `RunIslandMainProcess` sets `root_cache_path = IslandWebDataRoot()` and creates the directory
    `0700`.
  - In the persisting shape (`persist_session_ == true`, `browser_window.cc:255`), every space
    context gets `cache_path = <root>/Spaces/<web_data_key>` (R-D3) and
    `persist_session_cookies = 1`.
  - The global context keeps an empty `cache_path`, so local pages stay in memory.
  - The smoke and headless shapes keep `""`, so tests stay in memory and deterministic.
  - This needs a seam: `Space` gets the path from the window, either as a stored
    `web_data_path_` or as the argument of `request_context()`. It must not reach
    `DefaultSessionFilePath()` itself.
  - CEF requires every context path to sit under `root_cache_path` (`cef_types.h`). R-D1's layout
    guarantees that.
  - **Check:** `SpaceTest.PersistingShapeUsesWebDataPathUnderRoot` (no CEF: assert the computed
    settings through a test hook); `SpaceTest.HeadlessShapeStaysInMemory`; B1 and B2 marked
    "sign-in kept" (TEST-PLAN §3.4); the same sign-in absent from a second space.
- **R-D3 — Directory key, not `SpaceId`.**
  - The directory key is a random 128-bit hex `web_data_key`, stored as an optional field on each
    space in `session.json`.
  - It is not the `SpaceId`, because `SpaceId` is reused:
    - `NextSpaceId()` restarts after the largest restored id (`tab_id.h:53-65`,
      `browser_window.cc:346`).
    - After a session load error, the new Default space starts again at id 1 (`:257-259`).
    - A `SpaceId`-keyed directory would hand a deleted or unrelated space's sign-ins to a new space.
  - A space restored without a key (a 0.9 session) gets a new key on its first save.
  - Keys are never reused.
  - **Check:** `SessionStoreTest.WebDataKeyRoundTripsAndIsOptional`;
    `BrowserWindowTest.NewSpaceAfterDeletingHighestIdGetsFreshWebDataKey`.
- **R-D4 — Session schema stays version 1.**
  - `web_data_key`, `routes` (§2.5) and `import_key` (§2.4) are optional members. `session_store.cc`
    ignores unknown members and checks only `version == 1`, so a 0.9 build still reads a 0.10
    session.
  - Known limitation: 0.9 drops the fields when it rewrites the session. A later 0.10 then issues
    new keys, so those spaces are signed out. The leftover directories are orphans (R-D5).
  - **Check:** `SessionStoreTest.Loads090SessionFixture`;
    `SessionStoreTest.UnknownMembersIgnored` (extend the existing coverage if it is already
    there); UP1 (§5.3) from a 0.9.0 HOME.
- **R-D5 — Deletion only after release, and orphans are never swept after a load error.**
  - Deleting a space writes the tombstone `<root>/Spaces/<key>/.island-delete`. The directory goes
    at the next launch, before any context is created. CEF holds those files open while the context
    is alive, so `RemoveSpaceAtIndex` (`browser_window.cc:5127`) must not delete them.
  - At startup, a directory that has no tombstone and no matching key in a *cleanly loaded*
    `session.json` is an orphan. Orphans are logged and kept.
  - After any session load error (`browser_window.cc:310-313`), nothing is swept. Otherwise one
    corrupt `session.json` would erase every sign-in.
  - **Check:** `WebDataSweepTest.TombstonedDirectoryRemovedAtStartup`;
    `WebDataSweepTest.NothingSweptAfterSessionLoadError`;
    `WebDataSweepTest.OrphanKeptAndLogged`.
- **R-D6 — Delete space asks first (D3).**
  - `kCloseSpace` (`browser_window.cc:708-715`) and the other removal paths that the person starts
    (`:2278`, `:3339`) show a confirmation: "Delete <name>? Its tabs and its sign-ins are removed."
    It follows the existing overlay rules (`overlay_lifetime.h`).
  - Agent-initiated removal keeps its action-gate treatment.
  - **Check:** `BrowserWindowTest.CloseSpaceCommandRequiresConfirmation`; capture
    `delete-space-confirm-{native,arc,graphite}-{light,dark}.png`.
- **R-D7 — Reset a space's web data.**
  - Settings > Privacy gets "Sign out of all sites in <space>". It closes that space's browsers,
    gives the space a new `web_data_key` and a new context, tombstones the old directory, and
    reloads the tabs.
  - This is the only clearing control in 0.10. Without it, persistent data gives the person no way
    out short of deleting the space.
  - **Check:** `BrowserWindowTest.ResetSpaceWebDataRotatesKeyAndTombstonesOld`; K check: sign in,
    reset, reload, signed out.
- **R-D8 — Platform keychain behaviour under Q3(b).**
  - macOS keeps `use-mock-keychain` (`lifecycle_config.h:22-23`), so
    `WindowConfiguration.NeverReachesTheMacOSKeychain` (`tests/lifecycle_config_test.cpp:15-27`)
    stays unchanged.
  - Linux adds `password-store=basic` to `kBrowserProcessSwitches`, so no libsecret or KWallet
    prompt appears.
  - Windows uses DPAPI and needs no switch.
  - The comments at `lifecycle_config.h:14-21` and `app_runtime.cc:18-22,31-33` are rewritten to
    say that data is on disk and protected only by file permissions and a fixed key.
  - Under Q3(a), the macOS switch is removed instead and that test is replaced by
    `WindowConfiguration.UsesSystemKeychainWhenSigned`.
  - **Check:** `WindowConfiguration.LinuxUsesBasicPasswordStore`; H1 for "no Keychain prompt on
    first run" on a clean macOS account.
- **R-D9 — Single instance.**
  - The CEF singleton lock moves with the root. A second launch with the same HOME still hands off
    to the first one ("Opening in existing browser session").
  - After a `kill -9`, the next launch starts normally and is not blocked by a stale lock.
  - **Check:** PE1; §5.5 stale `Singleton*` check against the new root.

### 2.2 CDP port off by default

**Current behaviour (verified).**

- `kRemoteDebuggingPort = 9222` (`src/main/lifecycle_config.h:12`) is applied unconditionally
  (`app_runtime.cc:17`).
- `tests/lifecycle_config_test.cpp:12` asserts the value.
- The agent does not use the port. Page tools go through the in-process
  `CefBrowserHost::ExecuteDevToolsMethod` (`src/main/devtools_bridge.cc:142`).
- No script, test or workflow connects to 9222. The only other mention is a URL string in
  `tests/address_input_test.cpp:61`.
- CEF also honours a `remote-debugging-port` command-line switch (`cef_types.h`,
  `remote_debugging_port`), and Island does not disable command-line arguments. Setting the field
  to 0 alone therefore does not close the port. ROADMAP does not mention this.

**Requirements.**

- **R-C1 — Off by default.** `CefSettings.remote_debugging_port = 0`. In the browser process,
  `IslandApp::OnBeforeCommandLineProcessing` (`island_app.cc:19-29`) removes the
  `remote-debugging-port` and `remote-debugging-pipe` switches with `CefCommandLine::RemoveSwitch`
  unless the developer flag is present.
  **Check:** CO2 and AS15 on a packaged build: `curl -s 127.0.0.1:9222/json` is refused, also when
  the app is launched with `--remote-debugging-port=9222`. Add
  `IslandAppTest.StripsRemoteDebuggingSwitchesWithoutDevFlag`.
- **R-C2 — Developer flag.**
  - Island's own flag `--island-dev-remote-debugging[=PORT]`, default 9222, accepts ports
    1024–65535. It is parsed next to the other `--island-dev-*` flags (`dev_capture.cc:15-18`).
  - When it is on, CEF also gets `remote-allow-origins=http://127.0.0.1:PORT` instead of `*`.
  - Island prints `WARNING: remote debugging is on at 127.0.0.1:PORT; any local process can control
    your tabs` to stderr, and Settings > About shows "Remote debugging: on (port N)".
  - The flag works in every build, as Q4(b) requires.
  - **Check:** `DevFlagsTest.RemoteDebuggingFlagParsesPortAndRejectsOutOfRange`; capture
    `about-remote-debugging-on.png`.
- **R-C3 — The changed test is a requirement change, not a weaker check.**
  `WindowConfiguration.DefinesThePhaseZeroNativeWindow` (`tests/lifecycle_config_test.cpp:8-13`)
  changes to assert that the production port is 0. The new `R-C1` test keeps the guarantee it
  protected.
  **Check:** code review of the diff.

### 2.3 Crash-safe session saving

**Current behaviour (verified).**

- `SaveSession` (`browser_window.cc:487-492`) has exactly three callers:
  - the space color message (`:1873`);
  - `SetSpaceIcon` (`:3372`);
  - the clean quit, inside `if (persist_session_)` (`:4329-4330`).
- Opening, closing, moving, pinning and navigating tabs, renaming a space (`RenameSpace`,
  `:3355-3363`), creating or deleting a space, and the Arc import (`:2421-2431`) never save.
- ROADMAP ("сохраняется только при чистом выходе") is therefore almost right. The exceptions are
  two space-appearance edits.
- Those two calls ignore `persist_session_`, so a smoke run that changes a space icon or color
  writes the real `session.json`. That is a bug, fixed by R-S1.
- `SessionStore::Save` is already atomic: temp file, then rename (`session_store.h:120-126`).
- A load error falls back to a fresh session (`browser_window.cc:310-313`). The next save then
  overwrites the unreadable file with no backup (TEST-PLAN PR1). Debouncing moves that overwrite
  from quit time to a few seconds after launch.

**Requirements.**

- **R-S1 — One dirty mark.**
  - `MarkSessionDirty()` is the only entry point for change saves. It returns immediately unless
    `persist_session_` is set and `closing_` is clear.
  - It is called from `UpdateChromeCollections()` (`browser_window.cc:5079`), the funnel for
    tab-list and space changes, and from the main-frame address-change path for committed URL
    changes.
  - The direct calls at `:1873` and `:3372` become `MarkSessionDirty()`.
  - **Check:** `BrowserWindowTest.SpaceIconChangeInSmokeShapeWritesNoSession`;
    `BrowserWindowTest.TabOpenCloseNavigateRenameMarkSessionDirty`.
- **R-S2 — Debounce and maximum latency.**
  - A CEF-free `SessionSaveScheduler` with an injected clock saves 2 s after the last change, and
    at most 10 s after the first unsaved change while changes keep arriving.
  - The window drives it with `CefPostDelayedTask` on the UI thread, following the existing
    `Advance*ClockForTest` pattern (`browser_window.cc:4935`, `:5938`).
  - Once `closing_` is set, the scheduler is cancelled and the clean-quit save at `:4330` remains
    the final write.
  - **Check:** `SessionSaveSchedulerTest.DebouncesBurstsIntoOneSave`;
    `SessionSaveSchedulerTest.MaxLatencyBoundsContinuousChange`;
    `SessionSaveSchedulerTest.CancelledAfterClose`.
- **R-S3 — Testable path.**
  - `SaveSession` and `RestoreSession` take the session path from a member, set by default to
    `IslandDataDirectory()/session.json` and replaceable in tests.
  - Today both hardcode `DefaultSessionFilePath()` (`:310`, `:491`).
  - **Check:** used by every R-S test.
- **R-S4 — Unreadable sessions are kept.**
  - On a parse, schema or version error (not a missing file), the first save after launch copies
    the original bytes to `session.json.invalid.bak`, then writes. This matches the 0.9 bookmarks
    rule (TEST-PLAN BM2).
  - **Check:** `BrowserWindowTest.CorruptSessionPreservedAsInvalidBakBeforeFirstSave`; PR1.
- **R-S5 — Crash outcome.**
  - A `kill -9` of the main process with 10 tabs open restores at least 9 of them.
  - The changes lost are only those from the last ≤ 10 s, usually ≤ 2 s.
  - **Check:** TEST-PLAN §5.5 `kill -9` scenario (S+K), reported as restored/expected.

### 2.4 Arc import completion

**Current behaviour (verified).**

- `ParseArcSidebar` (`browser_import.cc:239-283`) reads the first `sidebar.containers` entry that
  has both `spaces` and `items`. From each space it takes the title, the color from `customInfo`,
  and the tabs under the container that follows the `"pinned"` marker in `containerIDs`.
- `CollectArcTabs` (`:97-122`) recurses into child items that are not tabs. Folders are therefore
  **flattened into pinned tabs**, and their titles are lost.
- Favorites ("top apps") are not read at all.
- Only `pinned` is used, so unpinned tabs are skipped by design.
- The file is found only at the default Arc location (`:285-308`). Linux returns nothing.
- Both the Welcome flow (`browser_window.cc:6229-6235`) and Settings (`:2088`) import Arc through
  `ImportFromBrowser` and `AddImportedSpaces` (`:2378-2410`). That path appends a new space for
  every Arc space each time it runs, so **re-importing duplicates spaces**. This contradicts
  ROADMAP F-6.
- `ImportFromSource(kArc)` (`bookmark_import.cc:194-204`) flattens Arc into plain bookmarks, but no
  UI path calls it for Arc, because `ImportFromBrowser` returns before reaching it (`:2420-2431`).
- An imported space with no valid pinned tabs is dropped (`:2398-2400`).
- The test fixture is synthetic (`tests/browser_import_test.cpp:156-175`). No real export has been
  parsed.

**Mapping (Provisional decision D1, owner to confirm).** These Arc structures are inferred from the
synthetic fixture and from Arc's observed layout. Every row marked † must be confirmed against the
real file (Q12) before it is implemented. If the real file differs, the plan changes the reader and
keeps the mapping.

| Arc | Island 0.10 |
|---|---|
| Space: title, color | Space (as today) with `import_key = "arc:<space id>"` |
| Pinned top-level tab | Pinned tab in that space (as today) |
| Pinned folder (any depth)† | Bookmark folder `Arc · <Space> · <Folder>`. Nested folders flatten into one folder whose name is the path joined with ` / `, because 0.9 folders are one level deep (0.9 spec §2.1) |
| Favorites (top apps)† | Bookmarks in folder `Arc · Favorites`, each added to **global** favorites in Arc order, up to the 0.9 overflow rule (0.9 spec §3.1) |
| Unpinned / Today tabs | Not imported (non-goal) |
| Space with no pinned tabs but with folders or Favorites | Still created, with one start-page tab. Today it is dropped |

**Requirements.**

- **R-I1 — The reader returns structure.**
  - `ImportedSpace` gains `folders` (path plus items), alongside `pinned_tabs`, which now holds
    top-level tabs only.
  - A new `ArcImport` result adds `favorites` and the Arc space ids.
  - URLs keep passing `address_validator_` when tabs are created (`:2389-2393`). Bookmarks follow
    the 0.9 permissive import rule (0.9 spec §2.2).
  - **Check:** `BrowserImportTest.ArcFoldersKeepTitlesAndOrder`;
    `BrowserImportTest.ArcNestedFoldersFlattenToPathNames`; `BrowserImportTest.ArcFavoritesInOrder`
    (synthetic fixtures).
- **R-I2 — Re-import is idempotent.**
  - An Arc space whose `import_key` already exists in the session merges into that space. It only
    gains pinned URLs it lacks, compared case-insensitively, the same way bookmarks de-duplicate.
  - It is not renamed or recolored.
  - Bookmarks and favorites de-duplicate through `BookmarkStore::Import` and `AddFavoriteByUrl`
    (0.9 behaviour).
  - The status line reports added and skipped counts.
  - **Check:** `BrowserWindowPagesTest.ArcReimportAddsNoSpacesOrTabs` (extends the test at
    `tests/browser_window_pages_test.cpp:335`); IM1 run twice.
- **R-I3 — Import from a chosen file.**
  - Settings > General > Import gets "Choose Arc sidebar file…", which uses the existing
    `RunFileDialog` pattern (`browser_window_research.cc:1233`) in open mode.
  - The person can then import a `StorableSidebar.json` copied from another Mac or kept after Arc
    stops working, and Linux users get a path at all.
  - Files larger than 64 MiB are rejected, as `ReadWholeFile` does today (`browser_import.h:58`).
  - **Check:** `BrowserWindowPagesTest.ArcImportFromChosenPath`; capture
    `settings-import-arc-file.png`.
- **R-I4 — The import is saved at once.** A successful import calls `MarkSessionDirty()` (R-S1).
  Today the imported spaces exist only in memory until a clean quit.
  **Check:** covered by `BrowserWindowTest.TabOpenCloseNavigateRenameMarkSessionDirty` (import
  case).
- **R-I5 — Verified on a real file (Q12).**
  - Acceptance needs a real `StorableSidebar.json` from the owner or a volunteer, never committed.

### 2.5 Space routing

**Current behaviour (verified).**

- Tabs open in the active space only: `AppendTabToActiveSpace` (`browser_window.cc:751`).
- Its callers that open a URL in a new tab are:
  - `OpenNewTab` (`:779-790`), for addresses typed into a new tab;
  - `OnPeekOpenAsTab` (`:3954-3962`);
  - `ReopenClosedTab` (`:2455-2462`).
- Web-initiated new-tab opens (⌘-click, middle-click, `target=_blank`) become Peek cards
  (`:3828-3843`, `:3847-3854`).
- Palette bookmark and history opens navigate the current tab (`:6265-6281` through
  `SubmitPaletteUrl`).
- There is **no tab context menu**. The menus are the page context menu (`OnBeforeContextMenu`,
  `:3859-3884`) and the macOS Browser menu (`main_mac.mm:719` onwards). ROADMAP's "пункт
  контекстного меню" therefore has to mean the page context menu.

**Requirements.**

- **R-R1 — Rule model.**
  - A rule is a host pattern stored in the target space's `routes` array in `session.json` (R-D4),
    for example `"github.com"`.
  - A rule matches the host itself and its subdomains, after the same normalization the address
    parser applies.
  - A host can be routed to only one space. Adding it to another space moves the rule and says so.
  - The longest matching pattern wins.
  - Rules die with their space and are covered by backup (§2.6).
  - The logic lives in CEF-free `src/main/space_routing.{h,cc}`:
    `RouteForUrl(url, rules) -> optional<SpaceId>`. It is a table lookup, ready for the 0.11
    external-URL path.
  - **Check:** `SpaceRoutingTest.SubdomainMatches`; `SpaceRoutingTest.LongestPatternWins`;
    `SpaceRoutingTest.OneSpacePerHost`; `SpaceRoutingTest.IgnoresNonWebUrls`;
    `SessionStoreTest.RoutesRoundTripAndAreOptional`.
- **R-R2 — Where routing applies.**
  - It applies to `OpenNewTab` and `OnPeekOpenAsTab`. A match whose space is not the active space
    opens the tab there (D4).
  - It does not apply to in-tab navigation, palette or bookmark opens in the current tab,
    `ReopenClosedTab`, favorites, Peek itself, session restore, or tabs the agent opens.
    Agent tabs stay where the action gate and the task queue put them.
  - **Check:** `BrowserWindowTest.NewTabRoutedToRuleSpace`;
    `BrowserWindowTest.InTabNavigationNeverRoutes`; `BrowserWindowTest.AgentTabsNeverRoute`.
- **R-R3 — "Always open in this space".**
  - The item appears in three places:
    - in the page context menu on web pages, as "Always open <host> in <space>"
      (`MENU_ID_USER_FIRST` range, next to "Open in peek");
    - in the macOS Browser menu, for the active tab's host;
    - in ⌘K as "Always open this site in <space>" and "Stop routing <host>".
  - Rules are listed and removed in Settings > Tabs, in a new group "Site routing".
  - No new native `ChromeViewId` is needed.
  - **Check:** `BrowserWindowTest.ContextMenuAddsRouteForActiveSpace`; K check: add a rule, open
    the host from another space, the tab lands in the rule's space; capture
    `settings-tabs-routing-{light,dark}.png`.

### 2.6 Backup and restore

**Inventory (verified).** The Island data directory (R-D1) contains:

| Path | Owner | In backup |
|---|---|---|
| `prefs.json` | `prefs_store.cc:402`, including the trusted sites (`prefs_store.h:66`) and the agent command (`:34`) | yes |
| `session.json` | `session_store.cc:335` | yes |
| `bookmarks.json` (+ `.v1.bak`, `.invalid.bak`) | `bookmark_store.cc:859` | yes (the `.bak` files are skipped) |
| `reports.json` | `report_store.cc:196` | yes |
| `history/index.seg` | `browser_window.cc:268-271` | yes (binary, base64) |
| `content-blocker/` | `content_blocker_policy.cc:10` | no: a regenerable list cache |
| `agent-endpoint.json` | `agent_endpoint.cc:60`, a 0600 bearer token (`:174`) | **never**: a secret, regenerated each run |
| `Web Data/` (R-D1) | CEF | no (D2) |

ROADMAP F-7 lists "trusted sites" as a separate item. They live in `prefs.json`. ROADMAP also
leaves history out of "all user data". This spec includes it.

**Requirements.**

- **R-B1 — One file.**
  - "Back up…" writes `Island Backup YYYY-MM-DD.islandbackup`, a JSON document:

    ```json
    {"format": "island-backup", "version": 1, "app_version": "0.10.0", "created": "<RFC 3339>",
     "files": {"prefs.json": {...}, "session.json": {...}, "bookmarks.json": {...},
               "reports.json": {...}},
     "binary": {"history/index.seg": "<base64>"}}
    ```

  - The file is written atomically with mode 0600. No archive library is needed.
  - The format is produced by CEF-free `src/main/backup.{h,cc}`, which decides which files to
    include from a table (`kBackupEntries`: path, kind, validator). A future file is added with one
    row.
  - **Check:** `BackupTest.WritesEveryTableEntryAndNothingElse`;
    `BackupTest.NeverIncludesAgentEndpointOrWebData`.
- **R-B2 — Validate before restore.**
  - "Restore…" parses the file and rejects anything with an unknown `format` or a newer `version`,
    or larger than 256 MiB.
  - Each entry goes through its own store's `Load` (`SessionStore::Load`, `PrefsStore::Load`,
    `BookmarkStore` load, `ReportStore::Load`). If any entry would fall back to defaults, nothing is
    restored.
  - **Check:** `BackupTest.RejectsInvalidEntryWithoutTouchingFiles`;
    `BackupTest.RejectsNewerFormatVersion`.
- **R-B3 — Staged restore and relaunch.**
  - The running window saves the session at quit (`:4329-4330`) and through R-S2, so restored files
    written in place would be overwritten.
  - Restore therefore writes `restore-pending/` next to the data files and asks the person to
    restart Island.
  - At the next launch, before any store loads, Island:
    1. copies the current files to `pre-restore-<timestamp>/`;
    2. moves the staged files in, one file at a time, each with an atomic rename;
    3. removes the staging directory.
  - If the launch is interrupted, the step either completes or leaves the old files in place.
  - **Check:** `BackupTest.StagedRestoreAppliedBeforeStoresLoad`;
    `BackupTest.PreRestoreCopyKept`; S check from ROADMAP F-7: back up, clean HOME, restore,
    relaunch, file-by-file comparison equal except `web_data_key` (D2).
- **R-B4 — Restored spaces get new web-data keys.**
  - With D2 = no web data, every restored space gets a new `web_data_key`, so a restore never
    points a space at someone else's existing directory.
  - **Check:** `BackupTest.RestoreRotatesWebDataKeys`.
- **R-B5 — UI.**
  - Settings > General gets a "Backup" group with "Back up…" and "Restore…" buttons and the last
    backup date.
  - Restore shows a summary card before staging: counts of spaces, tabs, bookmarks and reports;
    changed preferences; and the security items from §6.4.
  - **Check:** capture `settings-backup-{native,arc,graphite}-{light,dark}.png`;
    `BrowserWindowPagesTest.RestoreSummaryListsAgentCommandAndTrustedSites`.

## 3. Data model

`session.json` stays at schema version 1. The new fields are optional (R-D4):

```json
{
  "version": 1,
  "active_space_id": 7,
  "spaces": [
    {"id": 7, "name": "Work", "color_argb": 4281558783, "icon": "briefcase",
     "web_data_key": "3f9c0d1e5a7b4c2d8e6f0a1b2c3d4e5f",
     "import_key": "arc:5B1E…",
     "routes": ["github.com", "linear.app"],
     "tabs": [...], "active_tab_id": 12}
  ]
}
```

On-disk layout:

```
<Island data dir>/            prefs.json session.json bookmarks.json reports.json history/
                              content-blocker/ agent-endpoint.json
                              restore-pending/        (only between Restore and relaunch)
                              pre-restore-<ts>/       (kept; the person may delete it)
<web data root>/              = <data dir>/Web Data   (macOS, Linux)
                              = %LOCALAPPDATA%\Island\Web Data (Windows)
                              = $ISLAND_DEV_CACHE_DIR (when set)
  Spaces/<web_data_key>/      one CefRequestContext cache per space
  Spaces/<key>/.island-delete tombstone, swept at next launch
```

Prefs gain only `last_backup_at` (int64, optional). `bookmarks.json` is unchanged (0.9 schema 2).

## 5. Lifecycle and edge cases

- **Session load error:** start fresh, keep the bad file as `.invalid.bak` (R-S4), sweep nothing
  (R-D5), and give new spaces new keys. Old sign-ins stay on disk as orphans until a later version
  offers to adopt or remove them.
- **Downgrade to 0.9:** see R-D4. Sign-ins of spaces that 0.9 rewrote are orphaned on return to
  0.10, and nothing is deleted.
- **Space deleted while its tabs load:** the browsers close first (`CloseSpaceBrowsers`,
  `browser_window.cc:5118`), then the tombstone is written. Deletion happens at the next launch.
- **Disk full or no permission on `Web Data`:** CEF falls back as it does for an unwritable
  `root_cache_path`. Island logs the failure and keeps running, and §5.5 "Диск" checks the
  message. A space never silently falls back to another space's directory.
- **Routing rule for a deleted space:** it disappears with the space.
- **Import while a restore is staged:** import is disabled until the relaunch, because the staged
  files would replace the result.
- **Two Island instances:** prevented by the singleton lock (R-D9). Developer runs with
  `ISLAND_DEV_CACHE_DIR` and their own HOME keep working side by side.

## 6. Security and privacy

1. **Web data at rest (Q3 b).** Cookies and site storage are on disk. Under the mock keychain they
   are encrypted with a fixed, publicly known key, which means that in practice only the `0700`
   directory protects them. The 0.10 release notes and the FAQ say this. Q3(a) in 0.13 replaces it
   with the Keychain.
2. **CDP (Q4 b).** Closed by default, including through the Chromium switch (R-C1). When the
   developer flag turns it on, it binds to 127.0.0.1 only, allows a single origin, prints a stderr
   warning and shows on the About page. The agent never depended on it.
3. **Per-space isolation.** One context directory per space and keys that are never reused (R-D3).
   Deletion is deferred until release (R-D5), and there is a reset (R-D7).
4. **Backup.**
   - The backup file is 0600 and never contains `agent-endpoint.json`, web data (D2) or
     credentials.
   - Restoring a foreign file can set `agent_command`, which is a program Island runs, and the
     trusted-site list, which skips action-gate prompts.
   - The restore summary therefore shows the agent command verbatim and lists every trusted site.
     Each of the two is restored only if its own checkbox is ticked, and both are unticked by
     default.
   - MCP configuration in prefs follows the same rule.
5. **Import.** Arc files are read with the existing 64 MiB cap and depth limits
   (`browser_import.cc:99`). URLs that become tabs pass the address allow-list. A chosen file is
   read once and never kept.
6. **Agent.** No new agent tools. Routing does not apply to agent tabs (R-R2). The agent cannot
   start a backup, a restore, a space reset or a routing change. None of these is exposed through
   MCP or ACP in 0.10.
