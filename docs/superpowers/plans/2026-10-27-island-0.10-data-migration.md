# Island 0.10 Data and Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sign-ins persist per space, the CDP port is closed, the session survives a crash, a
second launch shows Island instead of a stock Chromium window, Arc users can move over without
duplicates, hosts route to a space, and Island backs up to one file.

**Architecture:** Every rule lives in a CEF-free module with its own tests (`data_paths`,
`web_data`, `session_save_scheduler`, `space_routing`, `backup`, the Arc reader). The window side
of each feature is a separate `browser_window_<feature>.cc` file of `BrowserWindow` member
definitions, following `browser_window_research.cc`. `browser_window.cc` only gets call-site
hooks of a few lines each, because the 0.9 refactor AR-1 ("displayed tab") is being worked on in
that file.

**Tech Stack:** C++20, CEF 150 `cef_views`, GoogleTest, the in-tree `json` reader/writer, local
HTML pages (`src/main/pages/settings.html`), pytest for scripts.

**Spec:** `docs/superpowers/specs/2026-10-27-island-0.10-data-migration-design.md` (accepted
2026-10-27). Requirement IDs (R-D1 …) refer to it. Read the spec section of each task before you
start. Runtime red evidence on 0.9: `~/hsse/agents/reports/research-1.0/recon/REPORT.md` and
`RESULTS.md` (2026-10-27, build `afce958`); each task below quotes the recon row it turns green.

**Out of scope (0.11):** permission prompts (recon B5), the downloads UI (B3), print and Save as
PDF (B6), and window fullscreen and the audio indicator (B10). Do not start them in 0.10 branches.

## Global Constraints

Every task follows these rules, together with `~/hsse/agents/prompts/common.md` and root
`AGENTS.md`.

- **Proof.** A new test fails on the pre-0.10 code and passes on the new code. Show both runs in
  REPORT.md. A changed existing test is a requirement change, so the commit message states the
  requirement ID and the reason (R-C3, R-D6).
- **Gates after the last change of each task:** `cmake --build build`,
  `ctest --test-dir build --output-on-failure` and `python3 -m pytest tests/design` are green. A
  task that touches `src/agent` also runs the standalone agent build from root `AGENTS.md`.
- **Test shapes.** Unit tests use `CreateHeadlessForTest` (`persist_session=false`). A test that
  needs the persisting shape constructs `new BrowserWindow(url, /*persist_session=*/true)` inside
  `ScopedDataHome` (T1), and never touches the real HOME.
- **Captures** use a fresh HOME and `ISLAND_DEV_CACHE_DIR` per run (common.md). From T11 onward,
  `ISLAND_DEV_CACHE_DIR` is also the web-data root, so a capture never touches the person's
  profile. Open every PNG before you list it.
- **Action gate.** The agent gets no new tools. Backup, restore, space reset and routing changes are
  not reachable through MCP or ACP (spec §6.6). Routing never applies to tabs the agent opens
  (`opened_by_agent`). Nothing in 0.10 skips `src/agent/action_gate.*`.
- **Overlays exist only while shown** (`src/main/overlay_lifetime.h`). The delete-space
  confirmation and the restore summary reuse existing surfaces (the palette overlay and the
  Settings page). No `ChromeViewId` is allocated (spec §4).
- **Theme tokens only.** Use neutral selected states, neutral rounded focus rings, and the accent
  only where it is already allowed. Destructive buttons use the existing danger tokens of
  `settings.html`. Every new surface is captured in Native, Arc and Graphite × light and dark.
- **Hot-spot budget.** Each wiring task (Group B) adds at most about 40 changed lines to
  `browser_window.cc`. They are hooks only: one-line calls into the feature file, a `.Set(...)`
  line in the Settings JSON builder, and an `if (Handle<Feature>SettingsMessage(type, message))
  return;` line in the Settings message dispatch. Do not change `DisplayedTab`, `active_tab()`
  semantics or the favorite virtual-tab code, because AR-1 owns them. Rebase onto the integration
  branch before review.
- **Docs in the same commit.** Each touched directory's `AGENTS.md` (new files, extension points),
  `DESIGN.md` for UI, `CHANGELOG.md` under `## [Unreleased]` for user-visible changes (released
  sections stay byte-identical), and the matching `docs/user-guide/` page. Never describe a feature
  before it is built.
- **Session schema stays version 1.** New members are optional, and an unknown member is ignored
  (R-D4).
- **No version bump.** `VERSION` is bumped only by the owner's release PR.
- **Conventions.** Use explicit `std::`, Google style with 4-space indent and 100 columns, and
  clang-format the changed lines. Prefer tables over if-chains where more entries will come
  (`kBackupEntries`, the routing table).

## Review Focus

These are the inputs the spec implies but no requirement names, in order of likelihood. Each has
a test in the task that owns it.

1. **A malformed `web_data_key` in `session.json`** (wrong length, `../`, uppercase). A
   hand-edited or foreign session must never put a context path outside `<root>/Spaces/`. It is
   treated as missing and a new key is issued. Test `WebDataTest.RejectsKeyThatIsNotLowercaseHex32`
   in T6.
2. **A routing rule entered as a URL or with a port or trailing dot** (`https://GitHub.com/x`,
   `github.com:443`, `github.com.`). It is normalized to the host, or rejected. A rule never matches
   a lookalike host (`notgithub.com`). Tests `SpaceRouting.NormalizesPatternInput` and
   `SpaceRouting.DoesNotMatchSuffixWithoutDot` in T5.
3. **An Arc re-import after the person renamed the imported space or deleted a pinned tab.** The
   merge keys on `import_key`, not the name. A deleted tab is added again (the spec says it "gains
   pinned URLs it lacks"), and the space keeps the person's name. Test
   `BrowserWindowPagesTest.ArcReimportKeepsRenamedSpaceName` in T14.
4. **A save that fails (disk full, read-only data directory).** The dirty mark stays set, the next
   change retries, and nothing crashes or loops. Test
   `SessionSaveScheduler.FailedSaveStaysDirtyAndRetriesOnNextChange` in T4.
5. **A backup file whose session refers to a space id that the restored bookmarks do not have, or
   the reverse.** Restore validates each file through its own store. Cross-file references are
   accepted as the stores already accept them (favorites of a missing space are kept). Test
   `Backup.RestoresSessionAndBookmarksWithMismatchedSpaceKeys` in T9.
