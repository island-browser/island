# island

## Purpose

The Island resource root as it appears at runtime. The build stages this tree into
`<bundle>/Contents/Resources/island/`, adding a `fonts/` directory from the gitignored
`assets/fonts/` alongside the committed `icons/`.

## Contents

| Path | Description |
|------|-------------|
| `icons/manifest.json` | Declares every runtime PNG: name, color role, size, scale, path |
| `icons/LICENSE-LUCIDE-ISC-AND-FEATHER-MIT.txt` | License text for the upstream icon sets |
| `icons/source/` | The four source SVGs: `chevron-left`, `chevron-right`, `globe-2`, `rotate-cw` |
| `icons/png/` | 240 generated PNGs (10 icons x 3 tones x 4 sizes x 2 scales), named `<icon>-<role>-<size>@<scale>x.png` |

No `AGENTS.md` is generated below this level — `icons/png/` is machine-generated output and
`icons/source/` holds only vendored SVGs.

## For AI Agents

### Working In This Directory

- **Never hand-edit `manifest.json` or anything in `png/`.** Both are generated by
  `tools/icon_pipeline/`; edit the sources and regenerate.
- The root `CMakeLists.txt` fails configuration unless `manifest.json` declares **exactly 240**
  outputs, every declared path matches `^resources/island/icons/png/[^/]+\.png$`, and every file
  exists. It also requires the manifest and the license file to be present, pointing failures at
  `tools/icon_pipeline/run.sh verify`.
- Color roles in the filenames (`accent`, `secondary`, `text`) correspond to the design tokens in
  `src/main/design_tokens.h`; sizes are `13/15/16/17` at `@1x` and `@2x`.

### Testing Requirements

```bash
tools/icon_pipeline/run.sh verify
cmake -B build -S .
```

A configure that succeeds is itself the manifest/PNG integrity check.

## Dependencies

### Internal

- `tools/icon_pipeline/` (generator), `src/main/icon_catalog.{h,cc}` (runtime lookup),
  `src/main/design_tokens.h` (color roles), root `CMakeLists.txt` (gate and staging)
